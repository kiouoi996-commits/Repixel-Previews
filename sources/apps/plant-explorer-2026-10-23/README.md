# Plant Explorer — one-screen application demonstration

This reconstructs the supplied1448×1086 plant-care UI board as one working mobile application. It does not display the board's scattered screen arrangement. All17raster resources are native-resolution, lossless crops of the supplied original pixels; no replacement plant illustrations were generated. Editable text, buttons, tabs, inputs, filters, selection and navigation are rendered independently. Original source code, confirmed font identity, hidden route layouts and original motion were not supplied. Inter is a visual font match. The8second navigation and tap sequence is authored behavior.

## Run and reproduce

Serve the adjacent five live files over HTTP: index.html, assets.mjs, model.mjs, scene.mjs, live.mjs. The page begins on onboarding, and Get Started enters the Home catalog. The normal app stays idle until an action. Changes to collection/favorites/reminders/care tasks persist only in its versioned localStorage key. Reset affects only that demonstration. The explicit demo saves the visitor's state, plays a deterministic fixture, then restores it without persisting scripted additions/removals.

For reproduction use Node22+, npm install, Python3 standard library and FFmpeg on PATH. Run python download-assets.py to obtain/verify all pinned resources into assets/ and fonts/. Set FONTCONFIG_FILE to the absolute path of fonts.conf on Linux. Run node check.mjs. Run node render.mjs --stills for visual checkpoints and the Home poster, then node render.mjs. SHARP_MODULE can identify an already-installed Sharp module entry. The renderer converts WebP to in-memory PNG only for librsvg compatibility; public live sources keep separate asset URLs and never embed raster payloads.

Output:780×1640 portrait, one390×820 app viewport, H.264/yuv420p,30fps,240frames,8seconds, silent and faststart. The first and last source PNG bytes match; lossy H.264 decoding is not asserted to be identical. A persistent one-screen composition fills the video frame. Route transitions crossfade/settle within that viewport rather than moving several device mockups around a presentation board. The catalog poster is a single Home view.

## Design and registered source crops

Home keeps the greeting/Plant Explorer title, search and filter, Small Steps / Greener Days banner, three popular cards, four category tiles and five-item dock. Monstera detail keeps its large yellow illustration, separate top controls, white rounded content sheet, tags, care tiles, about text and collection action. Onboarding keeps the original plant illustration, three-line heading, explanatory copy and Get Started. Search, collection, care and profile compose the supplied standalone UI components into functional route layouts; their full-screen arrangements were not provided in the board.

The Monstera tile has an embedded small source heart. A separate opaque live favorite control covers that exact corner. The detail hero has two embedded source controls, covered by separate opaque back/favorite buttons. Care art includes a clipped calendar remnant covered by the live calendar control. The tutorial poster includes a play/bookmark remnant: both receive independent registered live controls. Neither a whole screen nor the supplied board becomes a runtime screenshot background. Some crops include their original background/occlusion; do not invent unseen image content or advertise upscaled crops as recovered high-resolution originals.

The board's collection caption says3of5 while only two checks are visible. The fixture resolves this visibly: start with Snake/Pothos2of5; adding Monstera gives3of5 with three checks. Repeated addition is idempotent, and removing Monstera returns2of5. Both the count and check states derive from one collection array. The care guide is an authored readable fallback for the visible tutorial affordance because the original3:24tutorial media was not supplied; configure actual media through the host provider when integrating. Unshown plant facts are fixture metadata, not expert horticultural guidance or recovered original data.
