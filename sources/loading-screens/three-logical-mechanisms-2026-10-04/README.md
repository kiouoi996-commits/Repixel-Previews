# Three logical loading mechanisms — 4 October 2026

The supplied PNGs are still references. Original animation code and typeface were not supplied. All motion is authored for this release. White lettering, the plane outline and stationary steps are extracted as clean transparent artwork; SVG contours are reproduction geometry traced from their visible pixels. Dot centers/radii and step-contact coordinates are measured. The runner is redrawn with articulated limbs and two-bone inverse kinematics so its feet make actual contact with the supplied tread positions.

167: Dot Wave Loader. Eleven centers stay fixed; a smooth periodic radius profile travels clockwise. No entire ring rotation.
168: Loop Flight Loader. Five tangent-continuous Bézier segments follow the supplied looping route. The plane points along the curve tangent, gently changes perspective, and exposes a stationary dashed wake only behind its tail. It brakes and holds at the upper-right; plane and wake fade before an invisible restart.
169: Step Climb Loader. Five alternating hops climb the six measured steps. Feet stay planted until take-off or after landing, knees and elbows articulate at fixed segment lengths, the torso leans into travel, and the landing compresses the body. Foot identities stay continuous across hop boundaries. The figure fades after the last tread and resets while hidden; steps and label stay still.

Download the published alpha artwork alongside the renderer, then run `python3 render-mechanisms.py --render 167` (or 168/169). The optional `--prepare` stage requires the original supplied PNGs named reference-1.png, reference-2.png and reference-3.png; it is not needed to reproduce the movie from the published prepared assets. Dependencies: Python, Pillow, numpy, scipy, contourpy, ffmpeg. Gallery output is silent H.264, yuv420p, faststart, 900×900, 30 fps, 240 frames, 8 seconds. Closed gallery sampling uses t=8*frameIndex/239; an application uses its actual elapsed clock and exits loading as soon as the real task completes. Parameters JSONs specify native geometry and authored timing. Reduced motion uses a readable still pose and real accessible status. No percentage or fake loading minimum is implied.
