# UNBOX — Gift Commerce Studio

A reusable gift-box commerce experience, not a payment processor or a connected Shopify application. Its value is the complete configurable journey: choose real component products, stay inside a physical box capacity, personalize an editable card, style the packaging, inspect the composed set and add the confirmed selection to a host cart. The demo uses a six-product fixture catalog and a local cart, clearly identified in the interface.

## Embed

Serve these modules and `component.css` together. Import `component.mjs`, mount one `unbox-gift-studio` element, then call its async `configure` method. Pass `products`, `rules`, `assets`, optional `state` or `seed`, an optional unique `storageKey`, an optional canonical `shareBaseURL`, and host callbacks `onQuote` and `onAddToCart`. There are no framework, GSAP or Three.js requirements. This is a layered spatial composition made from independent transparent photographic assets, a photographic lid mapped onto authored perspective geometry, native text and Canvas drawing; it is not a true volumetric product model or a free-orbit 3D viewer.

Each product has a unique safe string `id`, human `name`, integer minor-unit `price`, integer `stock`, integer `spaces`, an asset key, a category and optional host `variantId`. All asset URLs must allow cross-origin Canvas use if export is enabled. Font files and their Poppins OFL license are listed in `assets.json`. Poppins is a licensed implementation match to the visual direction, not a claim about an unknown generated font. Do not copy private source screenshots into the runtime.

The default fixture rules are USD, six capacity units, two minimum items, three maximum units of one product, an $8 packaging charge and a 10% contents saving from four items. The candle and cup each occupy two units. Gold ribbon adds $4; the other ribbon choices are included. Discount rounding uses integer cents and never discounts packaging. Host integrations must replace fixture products, stock, business rules and messaging with actual data. Curation is deterministic bounded search over up to fourteen in-stock products, preferring distinct products, capacity use and then spend within the budget. It is not an AI service and does not reserve inventory.

## State and privacy

`unbox:change` provides the current configuration and derived estimate. Shared links contain only product IDs, quantities, box color and ribbon choice. The gift message, signature, prices and inventory are omitted and re-derived on restore. Untrusted restore data is bounded against the current catalog and capacity. `Save draft` is an explicit localStorage write, including the note, only when the host supplies a storage key. No automatic personal-text persistence, tracking endpoint, email or external share action is performed. The live example's optional integration log stays in the page's memory and displays an actual local callback payload.

Use `textContent` or escaped HTML for catalog names and personal text. Do not interpret a gift note as HTML. The 120/32 limits count Unicode characters. Browser storage failures and blocked clipboard access have visible fallbacks. A saved draft or share link never becomes a price authority.

## Cart integration

`onQuote(payload, {signal})` returns fresh `products` and optional `rules`. The component revalidates availability, selected quantities, selected variant identity, unit prices, currency and total before mutation. A difference restores an available set, shows a review message and requires a second user action. Configure this callback for a production integration. It must represent the store's actual pricing and discount policy, not return client estimates without checking them.

`onAddToCart(payload, {signal, idempotencyKey})` performs the host action and resolves only to `{status: "added", id: <actual receipt identity>}` after acceptance. It receives component identities, quantities, packaging, the gift note and a clearly labeled estimate. The host handles discounts, inventory, tax, shipping, authentication and payment. One active submission disables editing; double clicks cannot start parallel additions. A failed attempt retains its request key until the configuration changes. The host must honor that key atomically and reconcile ambiguous network failures before retrying. AbortSignal is a cancellation request, not a guarantee that a remote mutation was undone. Stale responses after disconnect/reconfigure are ignored. `unbox:added` is emitted only after an accepted receipt. An event or a film frame never substitutes for cart confirmation.

`cart-contract.mjs` maps a validated payload to Shopify Ajax `items`, including a real packaging variant and line item properties for grouping and gift instructions. It rejects placeholder/non-numeric variant IDs and cross-origin theme roots. This mapper does not send a request. Shopify's Ajax API is for Shopify-hosted themes and supports a locale-aware `cart/add.js` request with multiple variants. A headless storefront needs its own Storefront API adapter. A configured Shopify Function or equivalent store rule must actually apply any advertised discount. Shopify Ajax add requests do not provide this component's backend idempotency contract: a merchant adapter must reconcile uncertain additions, rather than blindly retrying. Consult the current official API documentation: https://shopify.dev/docs/api/ajax/reference/cart and https://shopify.dev/docs/api/ajax.

The local example bag mirrors confirmed demo receipts; it is not a live Shopify cart. In an actual store, use the host receipt/cart UI and implement removal in that store. The demo's Remove gift button only removes a local example receipt. No checkout form, fake payment success, shipment notification or third-party analytics is included.

## Motion and reels

The default interface is idle. Selection arrivals, packing, opening, lid travel and ribbon appearance use short interruption-safe interpolation, independent of logical item selection or price calculation. Native buttons and form fields remain the accessible input layer; Canvas is decorative. Hidden tabs, disconnection and completed motion stop requestAnimationFrame. `prefers-reduced-motion` skips stage travel and shows a static reveal instead of automatically playing a reel.

`Watch the magic` opens an opt-in 9:16 cinema for the actual current set and note, with Play/Pause and native Escape/Close. It never changes the configuration or calls a cart callback. The supplied catalog preview and vertical MP4 are authored reconstructions using the same stage painter and a fixed demonstration set. They are not browser recordings or evidence of a live order. The twelve-second composition starts with the products, nests them, presents the card, lowers the separate lid, draws the ribbon and reopens to the exact source starting pixels. A curved pointer with variable-speed transfers appears only in the desktop authored preview.

`Save gift image` creates a real local PNG from the current configuration. It requires loaded images with CORS permission. The optional deployment `release.json` enables a link to the fixed vertical demonstration MP4; it is publication metadata and is not required to embed the component. It does not export a custom movie for every visitor. The vertical cinema is suitable for screen recording personalized demonstrations.

## Responsive and accessible behavior

Desktop uses a large stage and a compact product/configuration panel. At 740 px the stage precedes a full-width native panel. Small-screen product quantity targets are at least 44 px; desktop targets stay comfortably usable. At 320 px the type and geometry reflow rather than squeezing the desktop interface. Fill/Personalize/Wrap are buttons with a current-step announcement and arrow/Home/End navigation. Native dialogs provide focus containment, Escape and focus return. Prices, inventory errors, quote changes and cart outcomes are announced through status text. All text remains selectable/readable DOM; the visual gift card additionally mirrors the message on Canvas.

## Validation and provenance

Run `node tools/unbox-gift-studio/verify.mjs` from the Repixel root for commerce, capacity, stock, sharing, curation, mapper and loop checks. `render.mjs` generates both movie formats with the shared painter; it verifies frame count, H.264 format, duration, one silent video stream and identical initial/final source pixels. Build the catalog with Repixel's normal animation generator and full build. The fixture and its imagery are a fictional authored product range, not manufacturer photography or a merchant's live inventory.

The visual direction was newly generated from the owner's “Мобайл Скрин” OAT & MILL reference (cream/blush/burgundy/apricot, friendly rounded typography and floating physical products) with the online-store reference informing spacing. Nine original transparent runtime assets were separately generated; source boards and the full concept mockup are not redistributed. All new images and movies belong in the public media repository at immutable commit-pinned URLs, with anonymous length/SHA-256 verification before catalog publication.
